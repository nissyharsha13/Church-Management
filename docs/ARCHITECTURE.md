# Architecture

## Overview

```
┌──────────────────────── one computer (today) ────────────────────────┐
│                                                                       │
│  Planner pages ──► IndexedDB (Dexie) ◄── Console (/present/[id])      │
│  /, /sermons/[id],    sermons, media,       │  useController()        │
│  /library, /settings  mediaFiles(Blob),     │  (source of truth)      │
│                       sessions, churches    ▼                         │
│                                       PresenterTransport              │
│                                       (BroadcastChannel)              │
│                                             │  state / media cmds     │
│                                             ▼  ▲ hello/ping/status    │
│                                       Display (/display)              │
│                                       <Stage> + <MediaPlayer>         │
│  public/bibles/<tr>/<BOOK>.json ──► loader (memory → Cache Storage → network)
└───────────────────────────────────────────────────────────────────────┘
```

## Folders

```
src/
  app/                    routes (thin). (app)/ = pages with the header
  lib/
    bible/                canon, reference parser, loader, slide builder, translations
    i18n/                 UI dictionary (en, te) + hooks
    db.ts                 IndexedDB schema (Dexie)
  modules/
    sermons/              types, repo, editor components, autosave hook
    media/                media types, helpers, icons
    presenter/            protocol, transport, Stage, MediaPlayer, controller, camera
scripts/bibles/           fetch + build pipeline for Bible data
public/bibles/            generated Bible data (committed)
tests/e2e/                browser smoke test + fixtures
docs/                     you are here
```

Each future module (choir, events, donations…) gets its own `src/modules/<name>` folder and routes. Shared concepts such as the church, people and services live in `src/lib`.

## Presenter

**Protocol** (`modules/presenter/protocol.ts`): the console sends the complete `DisplayState` (scene, language mode, camera, font scale, church name) on every change. The display is stateless and only renders what it receives:

- **Scenes**: `blank`, `logo`, `title`, `camera`, `verse` (one slide's verses in both languages), `media`.
- **Media commands** (`play`, `pause`, `restart`) are separate messages tied to a `nonce`, so a stale command can never affect a different clip.
- **Display → console messages**: `hello` (on load; the console replies with the state), `ping` every 1.5 s (connection indicator), and `media-status` (progress and ended).

**Transport** (`transport.ts`): an interface with `send` and `subscribe`. Today it's a BroadcastChannel (same browser, same computer). A WebSocket or cloud-realtime transport can be swapped in for multi-device control without changing the console or display (Phase 4).

**Controller** (`useController.ts`): all console actions are plain functions (`showVerse`, `gotoSlide`, `showMedia`, `blank`, `clear`…). Buttons, keyboard shortcuts and the future AI listener all call the same functions.

**Failsafes**
- The console persists its state in `localStorage` per sermon. Reloading the console resumes the same screen, slide, pointer and timer.
- The display keeps its last state in `sessionStorage`, re-sends `hello`, and resumes after a reload.
- `actionSeq`: an async verse load is discarded if any newer action happened while it was loading, so the newest action always wins.
- When a video ends, the screen returns to the background (camera, or logo).
- Blank, Logo and Clear are always one click or key away.

**Stage** (`Stage.tsx`) is shared by the display and the console's live monitor. All sizes use container-query units (`cqh`/`cqw`), so the monitor is an exact miniature of the projector. Text size is chosen from the text length (`fit()`) and adjusted by the console's font-scale control.

## Bible data

- Generated by `scripts/bibles/build.mjs` from public-domain or openly licensed sources (see BIBLES.md).
- Format: `public/bibles/<translation>/<BOOK>.json` → `{"c": [[verse1, verse2, …], …]}`. `""` means missing; `"^3"` means "printed together with verse 3" (combined ranges like IRV `3-4`).
- `book-meta.json` holds KJV verse counts for the pickers. `canon.json` holds book ids (USFM) and English and Telugu names and aliases for the parser.
- The loader checks memory, then Cache Storage, then the network. *Settings → Offline Bibles* pre-fills Cache Storage.
- Slides: a passage is split by a character budget (`slides.ts`), so long passages page instead of overflowing.

## Data storage

Local-first IndexedDB (see DATA-MODEL.md). Uploaded media is stored as Blobs, so it plays offline. Every record carries `churchId` so a cloud database can be added later for multiple churches (D-002).
